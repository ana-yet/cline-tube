Each item is intended for one focused Codex task/PR, though an `XL` item should be decomposed further by its human owner before execution if reviewability would suffer. The first table records scope and impacts; the second records completion and delivery controls. “Schema impact” means proposed work, not a migration created during this architecture pass.

## Backlog execution rules

- One task may not claim a dependent item complete merely because it created a shared abstraction.
- Every PR names requirement IDs, backlog ID, migration/API compatibility, tests, security impact, and rollback.
- Schema items use expand/backfill/verify/constraint/contract releases; no destructive finance rollback.
- `Highest` reasoning tasks receive a second human or independent-model review before merge.
- P0 is reserved for the five corrected release blockers and the production release that proves them resolved; P1 items remain mandatory before final submission.
